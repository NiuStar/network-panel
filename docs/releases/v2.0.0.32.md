# Network Panel v2.0.0.32

## 发布构建修复

- 完整包含 v2.0.0.31 的事务升级实现。
- 修复 v2.0.0.31 Docker 构建在 `go mod vendor` 阶段缺少 SQLite 工具链依赖校验条目的问题；补齐固定版本的间接依赖与 go.sum，不改变事务引擎代码。
- 发布验证新增 `go mod vendor` 门禁，避免测试通过但容器构建失败。
- v2.0.0.31 标签保持原样，不移动、不覆盖；本次 Docker 正式发布使用 2.0.0.32。

## 面板升级事务化

- 原生标准安装升级改为独立 systemd worker：固定 Release 标签，完整暂存与校验后才停止旧服务、备份并激活；失败回滚，只有 `COMMITTED` 表示升级成功。
- GitHub release API digest 与同版本 SHA256SUMS 交叉核验，禁止从 main 或静态源混用其他版本文件。新增 `panel-runtime-scripts.zip` 发布资产。
- 增加跨进程互斥、持久事务状态、受理与状态查询接口；SSE 只读，不再因重连启动升级，不在错误后发送完成。
- 新进程启动前绑定数据库路径、dialect、端口和配置摘要，启动后核对真实数据库路径、新 PID、程序 SHA、版本及健康状态。提交前业务/节点连接及定时任务保持维护门。
- SQLite 回滚覆盖主库、WAL、SHM 和 DELETE hot journal；旧持久记录缺少必要证据时阻止自动恢复。
- 两套前端单次提交、查询持久状态，只有同一事务 COMMITTED 才显示成功；断线、超时、回滚、未知状态不误报成功。
- 后端与两种 Agent 的报告版本统一为 `2.0.0.32`。继承此前严格证书 pin/SNI 修复，其未关闭兼容性边界仍以此前说明为准。

## 部署边界（必读）

- **Docker：禁止面板内在线覆盖容器二进制。** 升级按钮改为镜像升级说明，请通过宿主机镜像发布/重建流程升级并保留现有数据卷和配置。
- 原生自动事务升级仅适用于 root 管理的 Linux 标准 systemd 安装：`/opt/network-panel`、`/usr/local/bin/network-panel-server`、SQLite，架构 amd64/arm64/armv7；MySQL 默认拒绝自动升级，因为尚无完整数据库回滚链。
- **旧版本不能用旧在线升级入口安全自举新引擎。** 首次安装本版本须使用外部安装/升级流程；之后才能用新引擎升级满足资产契约的后续版本。
- 已完成真实 ELF 子进程、SQLite WAL/DELETE 日志回滚、跨进程锁/进程中断等候选验收；**独立原生 Linux 上完整 systemd-run/service 升级演练尚未完成**。本次发布不等于原生自动升级已获生产验收；先在隔离原生环境演练。
- 本次仅发布源码、Release 资产和镜像，**不切换生产容器、不重启面板或节点**。部署后如启用 Agent 自动升级，新预期版本可能触发节点升级，请沿用既有升级门禁。
