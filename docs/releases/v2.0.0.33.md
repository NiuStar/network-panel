# Network Panel v2.0.0.33

## 修复与优化

- AnyTLS 当前进程证书就绪状态独立持久化，不再依赖可裁剪诊断日志；保留真实启动屏障、同进程安装确认、时效、指纹匹配和新失败失效门禁。
- 两套出口编辑页面修复 SS/AnyTLS 异步回填串值、关闭重开后旧请求污染，以及证书开关加载导致协议重置的问题；保存必须绑定当前已加载的节点、协议和会话。
- 增加弹窗实例内待完成写请求互斥，加载、切换协议或重新打开不能释放已下发写请求的锁；旧回执不能关闭或提示到新表单。
- 节点列表的绑定状态读取改为每个可见节点最多一条最新完整日志，按时间和 ID 排序；最新 NULL/无效数据不回退旧成功，类别优先级和最近900秒完整统计不变。
- 为日志增加查询复合索引；MySQL LONGTEXT 使用前缀索引，不改列类型。启动时校验已有索引的有序列与前缀，在线 DDL 拒绝 COPY 回退，并限制锁等待及执行时间。

## 验证与边界

已执行完整后端测试、受影响 vet、SQLite 与 MySQL5.7 实库回归、两套前端构建、实际 React 并发回归及桌面 Chromium 隔离接口验收。生产已先通过独立不可变热修复镜像部署上述功能；实测节点列表从最高24秒级下降至约1秒内的后续请求，但不构成长时延 SLA。

本次统一后端与两种 Agent 的发行版本声明为2.0.0.33。Agent 除版本声明外没有新增运行逻辑变更。推送此 Tag 会触发仓库既有 Release 资产流水线；源码 Tag、GitHub Release、Docker版本镜像和生产激活分别验收。**不因合并或 Tag 自动替换生产容器、升级或重启 Agent/GOST，也不恢复未运行的 SS37170 服务。**

自动证书范围是部署配置：`ANYTLS_CERT_NODE_IDS=""` 表示所有合法受管节点（包括未来新增节点），证书数据库开关仍需开启，认证、安装确认和严格 pin 门禁不变。不会因发布自动修改其他部署的白名单。

部署新面板可能改变预期 Agent 版本；保持 `AGENT_AUTO_UPGRADE=false`，除非另行授权升级。Docker仍走宿主镜像重建，不使用面板内覆盖二进制。原生完整systemd升级演练、SQLite部分索引元数据、并发渲染及跨弹窗/跨标签写序列等未关闭边界沿用既有验收文档，不扩大保证。
